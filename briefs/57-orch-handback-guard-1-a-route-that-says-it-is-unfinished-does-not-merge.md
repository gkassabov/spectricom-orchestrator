## 2 · THE TARGET STATE (D-S7CORE13-02 · S1: a runnable predicate, not a symptom list)

**A route whose executor output advertises outstanding work never reaches a merge. It ends with status `incomplete` and the verdict `INCOMPLETE(executor)`, its work committed on a preserved route branch, and the merge target untouched.**

The predicate EXTENDS `canon_assert.py`. Place it after `check_gate_log_invariants` (`:753-779`) and before `# ── verdict building` (`:782`). No new module.

```python
@dataclass(frozen=True)
class OutstandingWorkRule:
    id: str                 # e.g. "background"
    pattern: "re.Pattern[str]"

@dataclass(frozen=True)
class HandbackViolation:
    log_file: str
    reason: str             # "outstanding-work" | "log-unreadable" | "no-toni-header"
    rule: str               # the rule id for outstanding-work, else ""
    line_no: int            # 1-based line in the log file; 0 when not line-specific
    line: str               # the matched line, stripped, truncated to 160 chars; "" otherwise

def load_outstanding_work_rules(path: Path) -> Optional[tuple[OutstandingWorkRule, ...]]: ...
def check_handback_invariants(log_file: Path, rules: Sequence[OutstandingWorkRule]) -> list[HandbackViolation]: ...
```

**`check_handback_invariants` is EMPTY WHEN CLEAN.** Set quantified over (A11): **the executor output of ONE `fire_toni` log**. That means every non-blank line strictly after the first 60-`=` rule that follows the `=== TONI EXECUTION ===` header, and strictly before the **last** 60-`=` rule that is followed within 3 lines by a line starting `Exit:` (the `:836` trailer). If there is no such trailer (the `:839-848` paths), the output runs to end of file. **Excluded from the set:** the header block, the trailer block, and blank lines. Then:
- The file cannot be opened or read (`OSError`, including not found) ⇒ exactly one violation, `log-unreadable`.
- Line 1 does not start with `=== TONI EXECUTION ===` ⇒ exactly one violation, `no-toni-header`.
- Otherwise, **at most one violation per rule**: the first output line it matches, in file order. Every rule is tested against every output line independently, and `^` anchors at the line start.
- **Empty executor output is NOT a violation.** It advertises nothing. That is a different question, named in §4.

**Unreadable IS a violation here, on purpose, and here is why.** `_landed`'s "unreadable is never a violation" rule exists because its violations authorise a destructive action (retiring a brief). This predicate's violations authorise only a **refusal to merge**, and a route with no readable closing words has given no evidence that it finished. The caller maps `log-unreadable` and `no-toni-header` to `BLOCKED(environment)`, not to `INCOMPLETE(executor)`. `fire_toni` creates the file before it spawns the child (`:828`), so a missing log in production is an environment fault by construction.

**`load_outstanding_work_rules` is the resolver (A10).** It reads `config/handback-guard.json`. The format is JSON, not YAML, so `canon_assert` stays stdlib-only (`:48-57`). The shape is `{"outstanding_work": [{"id": str, "regex": str, "evidence": [str, …]}, …]}`. It compiles each regex with `re.IGNORECASE`. It returns `None` (**insufficient**) when the file is missing or unreadable, is not valid JSON, has no non-empty `outstanding_work` list, has any entry lacking `id`/`regex`, has a duplicate `id`, or has a regex that fails to compile. **The phrase set lives only in that file.** Source holds the resolver, the shape and the `None` fallback, never a phrase. The caller maps `None` to `BLOCKED(environment)` `handback-guard-unconfigured` for every route it is asked to judge.

### The match set: a blocklist over the whole executor output. Decided, not left open.

**Recommendation: a named, evidence-backed blocklist evaluated over every line of the executor output. Not a positive-form "looks like a handback" check.** Measured on the corpus, here is why:
- **Positive form on the final line fails both required negatives.** 51's and 52's last lines are connector boilerplate (§1). No "handback shape" admits them without admitting anything.
- **Positive form on the whole output (e.g. "contains a §7 heading") refuses good routes.** In the 2026-09-20…27 window alone, it would have blocked 5 completed exit-0 routes whose output has no §7 marker: `28-date-6`, `29-meds-ui-1` (the `093126` attempt), `32-ui-cleanup-1`, `33-enc-type-2` and `46-date-8`. Route 46 merged as `4c8557d0`. It would also refuse every route whose brief never asked for §7, which is all history before S7, and every executor that writes its handback to a file instead (route 54 wrote `briefs/…handback.md`). Output shape is not stable enough to require. A false positive blocks a good merge, and the guard gets disabled.
- **The blocklist, over the whole output, has 27 true positives and 0 false positives on the 829-log corpus.** All 27 were read by hand and all 27 are outstanding-work endings. None of the 802 others trips it, including the eight named negatives in T4. Final-line only would catch 21 of 27.
- **The blocklist's known weakness is recall on a phrasing never seen before.** It is mitigated, not solved: the rules are config (a new phrasing is a JSON edit plus a corpus re-run with `handback-scan`, T3), and every rule names its evidence. **Say this weakness in the handback. Do not claim the guard is complete.**

**The rules to ship in `config/handback-guard.json`.** Six rules. Each is justified by the real logs it is drawn from. "Logs" is the count of corpus logs the rule matches (the rules overlap, and their union is 27). Regexes are shown raw. JSON-escape them in the file.

- **`background`** — `\b(?:going|running|still running|is running|are running|still in progress) in(?:to)? the background\b`. Drawn from **route 54** (*"Half B and the re-run are going in the background"*), plus routes 24, 30, 38, `s6s75-hrt-avs`, `s7core6-l2-0`, `drk-q10`, `pcfg-02b` and `pcfg-02c`. **9 logs.** It deliberately needs a progressive verb, so `s7core8-l4-1`'s *"All background work is now closed out"* does not match.
- **`waiting`** — `(?:^|[.;:!]\s+|\bI'?m |\bI am |\bam )waiting (?:for|on)\b`. Drawn from **route 53** (*"Memory recorded. Waiting for the final-tree baseline run to complete."*), plus routes 34, 36, 40, `s6s67`, `s6s75-hrt-doc`, `sit-t1`, `drk-q10`, `red-1` and `red-5`. **10 logs.** It must be sentence-initial or first-person, so third-person prose like "the test was waiting for a lock" does not match.
- **`will-resume`** — `\bI'?ll (?:pick (?:\w+ )?up|follow up|commit once|await|continue as soon|report once|be re-invoked)\b|\bI'?ll finish\b[^.\n]*\b(?:when|once)\b|\bwill (?:notify|re-invoke) me\b`. Drawn from **route 54** (*"I'll finish the gate row in the handback when they complete"*), plus routes 10, 24, 30, 34, 37, 38, 40, `s6s71`, `s6s75` ×2, `s6s76`, `mock-1`, `l11`, `l1-2`, `l2-0`, `pcfg-02b` and `red-1`. **18 logs.** A bare "I'll finish" is deliberately not matched. It needs a `when`/`once` in the same sentence.
- **`in-flight`** — `\b(?:suite|run|re-?run|gates?|baseline|vitest|tests?|half|batch(?:es)?)\b[^.\n]{0,60}?\b(?:still (?:running|in progress|executing)|in flight)\b`. Drawn from routes 25 (*"Final whole-repo unit run is in flight"*) and 38, plus `s6s71`, `s6s75-hrt-doc`, `l2-1`, `drk-q10`, `pcfg-02b` and `pcfg-02c`. **8 logs.** The subject must be a test or gate run, so "the live daemon is still running the old code" (the kind of line an orchestrator handback writes) does not match.
- **`pending-bullet`** — `^\W*pending\W*:`. Drawn from routes 24 (*"- **Pending**: whole-repo baseline, …"*) and 37. **2 logs.** It needs the colon straight after the word, so `fix-001`'s *"- Pending refills: dashboard used …"* does not match.
- **`cli-bg-ceiling`** — `^Background tasks still running after \d+s; terminating\.` This is the `claude` CLI's own message (`drk-q10`), so it is the only deterministic rule in the set. **1 log.**

**Done:** `check_handback_invariants` over route 54's real log returns violations for `background` and `will-resume`. Over route 51's and route 52's real logs it returns `[]`. Over the pinned corpus it returns the counts in AC-HG-02. And `_run_batch_inner` given route 54's log produces `FINAL STATUS: incomplete` with `MERGE_TARGET` unmoved. Done is not "a check now exists".

### T3 · reachability, and the corpus CLI (D-S7CORE9-01)

For a directory it scans the `toni-*.log` files in it (non-recursive). With no PATH, it scans `LOG_DIR/<log_subdir>` for every repo in `config/repos.yaml`.
